2. WHY WE NEED IT
-----------------
Building modern web applications requires a clear separation of concerns:
- **Client (Frontend)**: Handles user interaction, visually presents data, and provides a rich user experience. It runs in the user's browser.
- **Server (Backend)**: Handles business logic, security, authentication, and database access. It runs on a server host.
- **Database**: Safely persists application data (users, repositories, tasks, messages) so data is retained when browsers or servers restart.

Without backend & database layers, a frontend application cannot store user accounts or allow multiple developers to collaborate in real-time. The MERN stack uses JavaScript across both frontend and backend, eliminating language switching barriers for developers.

3. CONCEPT EXPLANATION
----------------------
- **Node.js**: A JavaScript runtime built on Chrome's V8 engine that allows developers to run JavaScript on the server.
- **Express.js**: A lightweight, minimal web framework for Node.js that simplifies handling incoming HTTP requests (GET, POST, PUT, DELETE) and returning JSON responses.
- **React.js**: A declarative frontend JavaScript library for building component-based User Interfaces.
- **Vite**: A modern build tool that bundles frontend code with Lightning-fast Hot Module Replacement (HMR).
- **MongoDB**: A NoSQL document database that stores data as flexible JSON-like BSON documents.
- **Mongoose**: An Object Data Modeling (ODM) library for MongoDB and Node.js that provides schema validation and database abstraction.
- **REST API (Representational State Transfer)**: An architectural standard for web services where frontend applications communicate with servers over HTTP using standardized methods (GET, POST, PUT, DELETE) exchanging JSON data.

4. IMPORTANT TERMINOLOGY
------------------------
- **Client**: The frontend application (browser) requesting data.
- **Server**: The backend application responding to client requests.
- **Endpoint**: A specific URL path (e.g., `/api/health`) on the server where an API accepts requests.
- **HTTP Status Code**: Standard numerical responses from the server (e.g., `200 OK`, `404 Not Found`, `500 Server Error`).
- **JSON (JavaScript Object Notation)**: Data format used for transmitting data between client and server.
- **Package / Dependency**: External reusable software module installed via `npm`.
- **Environment Variables (`.env`)**: Secret or configuration values (like database URIs or PORT numbers) stored outside the source code.

6. CODE CONCEPTS
----------------
### Express Server Setup (`server/server.js`)
```javascript
const express = require('express'); // 1. Import express framework
const cors = require('cors');       // 2. Import CORS middleware
const connectDB = require('./config/db'); // 3. Import DB helper

const app = express(); // 4. Create Express instance
connectDB();           // 5. Connect to MongoDB

app.use(cors());         // 6. Enable CORS so React on port 5173 can talk to Express on port 5000
app.use(express.json()); // 7. Middleware to parse incoming JSON request bodies

app.use('/api', require('./routes/health')); // 8. Register routes under /api prefix

app.listen(5000, () => {
  console.log('Server running on http://localhost:5000');
});
```

### Axios Client Fetching (`client/src/App.jsx`)
```javascript
import axios from 'axios';

// Axios sends an asynchronous HTTP GET request to backend endpoint
const response = await axios.get('http://localhost:5000/api/health');
console.log(response.data); // Received JSON object from server
```

7. API CONCEPTS
---------------
- **HTTP GET Method**: Used to request data from the server without modifying server state.
- **CORS (Cross-Origin Resource Sharing)**: Security feature in web browsers. By default, browser prevents JavaScript at `http://localhost:5173` from requesting data from `http://localhost:5000`. Using `cors()` in Express grants permission.
- **Route Handling**: Express maps HTTP request paths (like `/api/health`) to JavaScript callback functions that respond with JSON.

8. DATABASE CONCEPTS
--------------------
- **Document vs Table**: SQL databases use rows and columns in tables. MongoDB uses documents (similar to JSON objects) grouped in collections.
- **Mongoose Connection States**:
  - `0`: Disconnected
  - `1`: Connected
  - `2`: Connecting
  - `3`: Disconnecting
- Mongoose abstractly manages connection pooling, retries, and schema validation.

10. COMMON ERRORS
-----------------
1. **`ERR_CONNECTION_REFUSED`**: Occurs when React tries to call `http://localhost:5000` but backend server is not running.
   - *Fix*: Start backend server with `cd server` then `npm run dev`.
2. **`CORS Error` (`Access-Control-Allow-Origin missing`)**: Occurs when Express server does not use `cors()` middleware.
   - *Fix*: Ensure `app.use(cors())` is added before routes in `server.js`.
3. **`MongooseServerSelectionError`**: Occurs when MongoDB service is not started on host machine or MONGO_URI string is invalid.
   - *Fix*: Start local MongoDB service or verify connection string in `.env`.

13. INTERVIEW QUESTIONS
-----------------------
Q1: What is the purpose of middleware in Express.js?
A1: Middleware functions are executed sequentially during the request-response lifecycle. They can inspect, modify incoming requests, parse JSON data, check authentication, or handle errors before sending a response.

Q2: Why do we use Mongoose instead of the raw MongoDB driver?
A2: Mongoose provides schema validation, data modeling, type casting, middleware hooks, and clean promise-based query syntax out of the box.
